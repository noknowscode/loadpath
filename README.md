# Loadpath

- **Owner:** Matthew Mattei (@noknowscode)
- **Status:** ready for review
- **What it is:** A 2D truss workbench that solves as you draw: forces, utilization and deflection follow every drag.

A desktop workbench for 2D trusses that solves as you draw. Place nodes, connect them, pin some to the ground, hang loads, and every member shows the force it carries, its utilization, and the deflected shape. Drag a node and the whole load path re-solves on every pointer move.

Built with Uno Platform (`Uno.Sdk 7.0.5`, Skia renderer, SkiaSharp 4, the Simple theme of Uno Themes with the design's palette in `Styles/ColorPaletteOverride.xaml`) for four heads: desktop (Windows, macOS and Linux through Skia), WebAssembly, Android and iOS. It follows the system theme (a light blueprint sheet or a dark drafting table), lays itself out for phones, tablets and desktops, and edits by mouse and keyboard or by touch. The product and interaction design are in [`SPEC.md`](SPEC.md); this file covers what shipped, how it is built, and how it was validated.

## Run

```powershell
dotnet build Loadpath/Loadpath.csproj -f net10.0-desktop -p:LoadpathTargetFrameworks=net10.0-desktop
dotnet run --project Loadpath/Loadpath.csproj -f net10.0-desktop -p:LoadpathTargetFrameworks=net10.0-desktop
```

`LoadpathTargetFrameworks` limits the app to one head, so a build needs only that head's workload. This folder holds the one app project Studio opens; the unit tests (xunit) live in the development repository, [noknowscode/loadpath](https://github.com/noknowscode/loadpath), and cover the page model, the container, the engine, the tools, the document session and Core. Warnings fail the build (`TreatWarningsAsErrors`), except trim analysis, which reports only on Uno's and MVUX's generated code. The other heads: `net10.0-browserwasm` (`wasm-tools` workload), `net10.0-android` and `net10.0-ios` (macOS). The development repository's CI builds all four.

In Debug, set `APP_NO_HOTDESIGN=1` to skip `UseStudio()` when no DevServer is reachable (headless runs).

## What it does

| Capability | How it shows up |
|---|---|
| Live analysis | Direct stiffness solve on every edit, sub-millisecond for the samples. Status chip in the title strip, max utilization in the status bar. |
| Force ribbons | Member width scales with axial force; copper is tension, steel-blue is compression, and compression members carry a dark core line so sign is never color-alone. Overstressed members turn red with hatch ticks. |
| Tools | `V` select, `N` node (click a member to split it), `M` member (chains; click empty space to add a node), `L` load (click for 10 kN down, drag from a node to aim), `S` support (cycles pin → roller → none), `H` pan or hold `Space`. |
| Selection | Click, `Shift`-click, marquee (`Alt` selects what touches), `Ctrl+A`. The floating bar above a selection offers support, load, split, duplicate, delete. |
| Manipulation | Drag nodes or members with grid snap, alignment guides, `Shift` axis lock, `Alt` to disable snapping. Arrow keys nudge, `Shift` ×5. Load arrow tails are handles. |
| Inspectors | Summary, node (position, support, load fields), member (section, material, force, stress, utilization bar, buckling check), mixed (bulk actions). Sections drag from the inspector onto members. |
| Outline | Nodes and members with support badges and signed forces; click selects, hover highlights on canvas. |
| Display modes | `1` forces, `2` utilization ramp, `3` deflected ghost (exaggeration ×0.2 to ×3, stepped from the palette; the legend and the layers sheet show it), `4` labels, `5` reactions. |
| Commands | Every action is an `AppCommand` with one shortcut label. `Ctrl+K` opens a searchable palette; right-click opens element-specific menus. |
| Undo/redo | Every mutation is a reversible edit. Drags coalesce into one entry, and Esc mid-drag undoes that drag only. Opening a sample, loading a preset and pasting a design are undo steps too, so none of them asks first. `Ctrl+Z`, `Ctrl+Y`. The history remembers the save point, so undoing back to the saved state clears UNSAVED; branching away from it keeps the document dirty. |
| Persistence | `.loadpath` JSON documents (save, save as, open), view options persisted. The autosave restores on launch with the file the document belongs to and its unsaved changes still unsaved. New, Open and closing ask before dropping unsaved work: a Save / Discard / Cancel dialog on desktop and Windows, the browser's own "leave this page?" prompt on WebAssembly. |
| Share | `SHARE` or `Ctrl+Shift+C` copies a one-line share code (`LP1.` + base64url of the deflated JSON, about 460 characters for the Warren sample). `Ctrl+Shift+V` (or "Paste design" in the palette or empty state) loads a code, a code inside a chat message, or raw `.loadpath` JSON. Pasting is one undo step. Without a clipboard the code goes to `~/Documents/Loadpath/<name>.share.txt` and paste reads it back. |
| Presets | `PRESETS` opens a flyout with Pratt, Howe, Warren, K, Fink and scissor trusses, generated from span, panels and depth (rise for roofs), each with a live thumbnail. A preset ships with supports, panel-point loads (5 kN/m deck for bridges, 2 kN/m for roofs) and sections, so it solves at once. Loading one is undoable; the palette lists each preset at its defaults. |
| Failure highlighting | Members over capacity carry a red pill that names the mode: `BUCKLES 294%` or `YIELDS 118%` (the pill drops the verb when crowded). A member failing by buckling also gets its first Euler mode drawn beside it as a dashed red bow, with a legend entry. The summary inspector lists every failure worst first, with the force against Pcr or the stress against fy; a row selects its member. `J` steps through the failures, with a toast giving the position ("2 of 6"). |
| Upsize | `U`, the inspector's UPSIZE FAILING MEMBERS button, or the palette gives every failing member the lightest library section that carries it below 95 % utilization, as one undo step. A member keeps its material when that material has a working section. Redundant trusses are re-solved and resized until they settle. The toast reports the count and added mass ("Upsized 6 members · +157.3 kg"), and names any member no library section can carry. A passing member changes only if the upsize itself pushes it above 95 % (load moves in a redundant truss); one that was already near its limit and is not made worse keeps its section. |
| Lighten | `Shift+U`, LIGHTEN MEMBERS in the summary inspector, or the palette gives members the lightest same-material section that keeps every member under 95 % (or under its own utilization, if it was already above), as one undo step. It runs only when nothing fails, tries the heaviest members first and re-solves after each change, and leaves zero-force members alone because they often brace the frame. The toast reports the mass saved and the new max utilization: the Warren sample drops from 252 to 128 kg at 89 %. |
| States | Empty-state invitation with three samples, mechanism banner when the structure can move, a warning when parts are not connected to a support (they are left out of the solve instead of failing it), toasts for refused actions. |

**Decision: MVUX for the presentation layer, an imperative engine for the document.** `EditorModel` is a `partial record` whose states and feeds carry immutable records (`EditorStatus`, `InspectorContent`, `OutlineItem`, `PaletteItem`); the generated `EditorViewModel` is the page's DataContext and every view binds with `{Binding}`. Buttons bind generated commands; undo and redo are feed-gated (`Command.Create(b => b.Given(Status).When(s => s.CanUndo)...)`). `EditorEngine` owns the document, undo history, selection, viewport and tools, and raises events the model projects into states, because a solve on every pointer move cannot copy an immutable document per frame. Tradeoff: two layers, and a plain `ViewOptions` mirror of the option states for the renderer. The model's pieces (status, options, inspector, outline, palette, presets) declare their own states and share the model's `SourceContext`: the generated view model binds a state of another context read-only.

**Decision: one container for the app's services.** `App` builds an Uno.Extensions host (`UnoFeatures` `Hosting`, `Logging`, `ThemeService`) and `AppServices` registers the engine, the document session, the settings, the toast queue, the theme switcher, the close guard, the file pickers, the unsaved-changes dialog and the MVUX view model as singletons. The page is created by the frame, so it resolves them from `App.Services` in its constructor, on the UI thread; everything below it takes its dependencies through constructors, and the tests build the same container with their own UI thread and settings store. Code that needs the UI thread (MVUX runs commands off it) goes through `IUiThread`, so the page model runs in the tests. Logging goes through `ILogger`: Debug builds log the app's decisions, `LOADPATH_TRACE=1` adds every key, press and wheel step, Release logs failures; failures that escape every handler are logged and shown as a toast. Tradeoff: the hosting packages add to the WebAssembly payload.

**Decision (proposed, 2026-11-04): a failure nothing else caught keeps the app running.** `App` marks `UnhandledException` handled after logging it and showing a toast, because every edit is in the undo history and the autosave, and closing would drop the session the user can still save. Tradeoff: a corrupt state could outlive the exception; the toast says something went wrong so the user can save and restart.

**Decision (proposed, 2026-11-04): the deflection exaggeration stays a palette command.** README promised a slider that was never built; the copy now says what exists (×0.2 to ×3 in steps of 0.1, shown in the legend and the layers sheet). A slider in the layers sheet is a small follow-up if the owner wants it.

**Decision (proposed, 2026-11-04): a view the user moved is refit only when a narrower window would cut the structure off.** A fitted view follows every resize, as before. A moved view stays where the user put it, unless the whole structure was on the canvas before the resize and part of it is not after it; then it is fitted again. A view the user left partly off the canvas stays theirs. Tradeoff: a narrower window can undo a zoom the user chose.

**Decision (proposed, 2026-11-04): a custom app icon in place of the Uno template's.** The launcher, splash and gallery icon are one mark: a roof truss on a pin and a roller, white on the app's accent (the Light `PrimaryColor` #3446D6), drawn as flat strokes so it reads at 48 px. `Assets/Icons/icon.svg` (the accent square), `icon_foreground.svg` (the mark) and `Assets/Splash/splash_screen.svg` (the mark in the accent on white) keep the template's viewBoxes, so the Resizetizer's foreground scales (1.0 desktop, web and Windows, 0.80 iOS, 0.65 Android) keep it inside each safe zone.

**Decision (proposed, 2026-11-04): the showcase info file points at the sample's future home.** `.studiolive/sample.json` (sample id `loadpath`) gives its icon and screenshots as `https://raw.githubusercontent.com/unoplatform/Uno.Samples/master/studio/loadpath/.studiolive/...`, as the format guide's example does, so they resolve only after the move to Uno.Samples. Whether relative paths can be used instead is the Studio team's question 1 in uno-private#2444. The screenshots were taken from the desktop head at 1280 x 800 and 390 x 844 with the samples the Debug fixtures load (nothing debug-only is in the frame).

**Decision: one `SKCanvasElement` for the workspace, XAML for everything contextual.** Ribbons, labels, supports, guides and adorners must be pixel-registered with the structure, so they are Skia. The floating bar, banners, toasts and the drag ghost are XAML on an overlay layer positioned through the viewport transform. The renderer reads a `RenderSnapshot` built on the UI thread and holds no per-frame allocations beyond paths. There is no `CompositionTarget.Rendering` subscription; viewport animations run a timer only while moving.

**Decision: the Simple theme carries the look; Uno Toolkit for responsive layout.** The visual system is the blueprint drafting sheet (Inter for UI, JetBrains Mono for every number, hairlines instead of shadows), carried by Uno Themes so Uno Platform Studio's Themes tab and any other theme change reach it. `App.xaml` merges `SimpleToolkitTheme` (`UnoFeatures` `SimpleTheme`, `Toolkit`): its `Colors` point at `Styles/ColorPaletteOverride.xaml`, the design's full Light and Dark table on all 33 palette keys; `DefaultFontFamily` is Inter and `FontOverrideSource` (`Styles/TypographyOverride.xaml`) sets the design's ramp (11 12 13 14 22) and `MonoFontFamily`; `DefaultSpacing` 8 and `DefaultCornerRadius` 4 generate the `Space*` and `Radius*` tokens. Pages, styles, converters and the canvas use the role brushes (`OnSurfaceBrush`, `PrimaryBrush`, `OutlineVariantBrush`, `ErrorContainerBrush`...): the structure is drawn in Primary, construction lines are Primary blended into the paper, and failure is Error. The one colour with no role is Warn, the amber step of the utilization ramp, in `App.xaml`'s Light and Default dictionaries. Text uses the semantic styles (BodyMedium, LabelSmall, HeadlineSmall...); SAVE, the links, the outlined actions, DELETE, menus, flyouts, fields, check boxes, the progress bar and tooltips are the theme's styles with the design's sizes. List rows, square icon buttons, the segmented toggles, the reduce-noise switch, the tool button and the number field keep small templates on role brushes (Simple's button templates cannot stretch a row's content, and Simple has no segmented control). `utu:Responsive`, `ResponsiveView` and `utu:SafeArea` keep the title strip, the work area and the status strip inside the phone's visible bounds. Tradeoff: menus highlight with the theme's Primary fill, toolbar buttons are 40 px (were 38) and 14 and 18 px icons are 16.

**Decision: two themes, one identity.** Every palette role has a Light value (the blueprint sheet: paper `#F7F8FB`, near-black ink, blueprint-blue structure) and a Dark one (a drafting table at night: blue-slate paper `#10141B`, chalk ink, the structure in a lighter blueprint blue `#8FA0FF`). Views use `{ThemeResource}` role brushes; the canvas palette and the brush-key converters read the same roles for the window's theme through `ThemeLookup`, re-read them on `ActualThemeChanged`, and again when the theme recolours its brushes after a palette edit. The app follows the system by default; the `⋯` menu (and three palette commands) pin Light or Dark, and the choice is saved with the view settings. Text passes 4.5:1 in both themes (secondary ink 7.3:1 on the light paper). Dark is keyed `Default`, so Windows High Contrast falls back to it instead of failing to resolve.

**Decision: one responsive layout for the workbench.** `Themes/Layout.xaml` defines the app's only `utu:ResponsiveLayout` as `DefaultResponsiveLayout` (Normal 600, Wide 1100, Widest 1240): a docked 336 px inspector needs 1100 px to leave the sheet usable, and the docked outline docks from 1240 px as it always did. Widest shows outline, canvas and inspector; Wide docks the inspector with the outline as its second tab; Normal makes the inspector a side sheet over the canvas; Narrow (phones) turns the tools into a 44 px strip under the drawing, the inspector into a bottom sheet and moves secondary commands into the title's `⋯` menu. `Ctrl+\` and the title's inspector button toggle whichever the layout has. Tradeoff: Loadpath's breakpoints differ from the Toolkit defaults the other samples use.

**Decision: touch edits through the same tools.** A finger behaves like the left mouse button, but its press is held back until it moves (drag), lifts (tap) or rests (long press, the context menu), so a second finger can turn the touch into a pinch-zoom and pan before any tool acts. Fingers hit-test with 22 px radii (mouse keeps 6 to 9 px). A multi-select toggle in the floating bar stands in for Shift, the free-placement tool for Alt.

**Decision: detached parts are tolerated.** The solver finds connected components; a component with no support is excluded and reported instead of making the whole solve singular. A structure that is genuinely a mechanism still reports as one.

## Platform notes

- On desktop the window is sized at launch through `ApplicationView.PreferredLaunchViewSize`; resizing after creation raced the X11 Skia surface and produced a stale first layout. A self-healing check still nudges the size if the layout ever disagrees with the frame. WebAssembly, Android and iOS fill the browser or the screen.
- Files are read and written through `StorageFile` streams, never `file.Path`: a picked file is a browser handle or temporary copy on WebAssembly (saves go through `CachedFileManager`, which starts the download in browsers without the File System Access API) and a content URI on Android.
- On Linux the file pickers go through the xdg-desktop-portal. Without a session bus the app saves to `~/Documents/Loadpath` and says so in a toast. Heads with no Documents folder (WebAssembly, Android, iOS) fall back to the app's local folder.
- Share uses `Windows.ApplicationModel.DataTransfer.Clipboard`, which works on the X11 host; desktop also `Flush`es it so the code outlives the app. Any clipboard exception falls back to a `.share.txt` file in the fallback folder, and a toast says so when there is no folder either.
- `ItemsWrapGrid` is not implemented in Uno, so the preset tiles use `ItemsRepeater` with `UniformGridLayout`.
- Mouse-wheel zoom uses `PointerWheelChanged`. Synthesized X11 button-4/5 clicks arrive as plain presses on this host, so wheel zoom was not exercised headlessly; `Ctrl+=`, `Ctrl+-`, `Ctrl+0`, `Ctrl+1` and `F` were.
- `SKCanvasElement` ignores `UIElement.Opacity`; dimming is baked into the paints.
- On Uno 7 `SKCanvasElement` derives from `Grid`, which is not hit-testable without a background; the workspace sets a transparent `Background` so it receives pointer input (and keeps keyboard focus on the key sink).
- Mouse-wheel zoom is off on Android and iOS, which report no wheel delta; `Ctrl+=`, `Ctrl+-`, `Ctrl+0` and Fit remain. Cursor shapes are set on desktop and WebAssembly only.
- Documents and settings serialize through source-generated `JsonSerializerContext`s: the trimmed WebAssembly head turns reflection-based `System.Text.Json` off.
- Load and reaction arrows have a fixed pixel length, so where their labels are clear depends on zoom. The renderer keeps the label boxes drawn each frame and gives an arrow label the first of four spots (beyond the tail, further beyond, beside the tail outward, beside it inward) that misses them.
- MVUX generator notes: records carried by feeds are plain `partial record`s (no `required` members, no record structs), colors travel as resource keys resolved by a converter, and a `readonly record struct` with an `Id` property must not be `partial` or the key-equality generator emits a non-partial duplicate.
- MVUX runs generated commands and `ForEach` callbacks on a thread-pool thread. Anything that mutates the document (and therefore raises events that reach XAML) is posted back to the UI dispatcher through `EditorModel.Ui(...)`; without it the first edit of a transaction lands and the rest throw "dependency property system should not be accessed from non UI thread".
- When a focused element leaves the tree (a collapsing inspector panel, the closing palette) keyboard events lose their target; the page moves focus back to an invisible `KeySink` on selection changes and palette close.
